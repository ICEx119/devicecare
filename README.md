# DeviceCare: ระบบยืดอายุอุปกรณ์ไอทีของนักศึกษา

เว็บแอปต้นแบบช่วยนักศึกษาดูแลอุปกรณ์ไอทีด้วยตนเอง (SDG 12 การบริโภคและการผลิตที่ยั่งยืน)

## ฟังก์ชัน
- **สมาชิก**: สมัครและเข้าสู่ระบบ แต่ละคนเห็นเฉพาะอุปกรณ์ แจ้งเตือน และประวัติของตัวเอง
- **AI วิเคราะห์อาการ**: ผู้ใช้เล่าอาการเป็นภาษาธรรมชาติ แล้ว Claude วิเคราะห์สาเหตุที่เป็นไปได้ ระดับความมั่นใจ ความเร่งด่วน ขั้นตอนตรวจสอบเอง และกรณีที่ควรส่งช่าง พร้อมจับคู่กับคู่มือของระบบ (ดูหัวข้อ “AI วิเคราะห์อาการ” ด้านล่าง)
- **ข้อมูลส่วนบุคคล (PDPA)**: ยอมรับนโยบายตอนสมัคร หน้า `/privacy.html` และหน้า “บัญชีและข้อมูลส่วนบุคคล” ที่ดูข้อมูลที่เก็บไว้และลบบัญชีเองได้
- **ตรวจอาการเบื้องต้น**: เลือกประเภทอุปกรณ์และอาการ แล้วดูขั้นตอนตรวจสอบอย่างปลอดภัย พร้อมคำแนะนำว่าเมื่อไหร่ควรติดต่อช่าง
- **คู่มือดูแลอุปกรณ์**: การทำความสะอาด แบตเตอรี่ พื้นที่จัดเก็บ การใช้งาน และซอฟต์แวร์
- **แจ้งเตือนการบำรุงรักษา**: ตั้งรอบการดูแล เมื่อกด “ทำแล้ว” ระบบจะบันทึกลงประวัติและเลื่อนกำหนดครั้งถัดไปให้อัตโนมัติ
- **แจ้งเตือนทาง LINE**: ผู้ใช้แต่ละคนเชื่อมต่อ LINE ของตัวเอง แล้วรับสรุปงานที่ถึงกำหนดทุกวัน แม้ปิดหน้าเว็บ
- **ประวัติการดูแลและซ่อมแซม**: บันทึกวันที่ ประเภท รายละเอียด และค่าใช้จ่าย
- **แดชบอร์ด**: สรุปงานที่ถึงกำหนด ค่าใช้จ่ายรวม และอาการที่ตรวจบ่อย
- **ผู้ดูแลระบบ**: สถิติรวมของทุกคน ดูข้อมูลแต่ละตาราง และดาวน์โหลดเป็น CSV (เปิดใน Excel ได้)

## ตั้งผู้ดูแลระบบ
ใส่ชื่อผู้ใช้ในตัวแปร `ADMIN_USERNAMES` (ใน `.env` หรือ Environment ของโฮสต์) คั่นหลายคนด้วยจุลภาค แล้วรีสตาร์ท
บัญชีนั้นจะเห็นเมนู **🛠 ผู้ดูแลระบบ** — หน้านี้ไม่แสดงรหัสผ่าน session token และ LINE user ID

## วิธีรัน
ต้องใช้ Node.js 22.13 ขึ้นไป

```
npm install
npm start
```

จากนั้นเปิด http://localhost:3000 แล้วสมัครสมาชิก

## AI วิเคราะห์อาการ
| หัวข้อ | รายละเอียด |
|---|---|
| โมเดล | Claude Haiku 5.5 (`claude-haiku-5-5`) ผ่าน Anthropic SDK (`@anthropic-ai/sdk`) เปลี่ยนได้ด้วย `AI_MODEL` — เลือกเพราะทดสอบจริงตอบเฉลี่ยราว 5 วินาที ส่วน Opus 5.5 ใช้ 12–15 วินาที เกินเกณฑ์ 10 วินาที |
| โค้ดและ prompt | `ai.js` (system prompt, JSON schema ของผลลัพธ์, การตรวจข้อมูล) · route `/api/ai/*` ใน `server.js` |
| ข้อมูลที่ใช้ | ข้อความที่ผู้ใช้พิมพ์ + ประเภท/ยี่ห้อ/วันที่ซื้อของอุปกรณ์ที่เลือก + รายการอาการ 22 แบบจาก `seed.js` (ให้ AI จับคู่กับคู่มือที่ตรวจเนื้อหาแล้ว) |
| รูปแบบผลลัพธ์ | บังคับเป็น JSON ตาม schema (structured outputs): `status` (ok / need_info / out_of_scope), สาเหตุ, ขั้นตอน, ความมั่นใจ, ความเร่งด่วน, คำถามเพิ่มเติม |
| ข้อมูลผิดรูปแบบ | ตรวจที่หน้าเว็บและเซิร์ฟเวอร์ก่อนเรียก AI: ว่าง, สั้นกว่า 10 ตัว, ยาวเกิน 800 ตัว, ไม่ใช่ข้อความ, JSON เสีย |
| นอกขอบเขต / ข้อมูลไม่พอ | AI ตอบ `out_of_scope` (ไม่แต่งคำตอบ) หรือ `need_info` พร้อมคำถามกลับ |
| Prompt injection | ข้อความผู้ใช้อยู่ในแท็ก `<user_description>` และถือเป็นข้อมูล ไม่ใช่คำสั่ง · ผลลัพธ์ถูกจำกัดด้วย schema จึงไม่มีช่องให้แสดง system prompt |
| ผลคงที่ | ข้อความเดิมได้ผลเดิมภายใน 24 ชั่วโมง (cache ในหน่วยความจำ) |
| เวลาตอบ | ใช้ effort ต่ำ, timeout 15 วินาที, หน้าเว็บแสดงสถานะ “กำลังวิเคราะห์” พร้อมตัวจับเวลา และแสดงเวลาที่ใช้จริง |
| การใช้งานเกิน | จำกัด 15 ครั้ง ต่อผู้ใช้ ต่อ 10 นาที |
| การปฏิเสธ | ถ้าโมเดลปฏิเสธ (`stop_reason: refusal`) หน้าเว็บแจ้งให้เล่าเฉพาะอาการอุปกรณ์ · ถ้าเปลี่ยนไปใช้ Opus/Sonnet ระบบเปิด server-side fallback ให้อัตโนมัติ (Haiku ไม่รองรับ) |
| ประเมินผล | ทุกครั้งบันทึกในตาราง `ai_logs` (สถานะ ความมั่นใจ เวลา 👍/👎) ดูสรุปได้ในหน้าผู้ดูแลระบบ |

ตั้งค่า: สร้าง API key ที่ https://console.anthropic.com แล้วใส่ `ANTHROPIC_API_KEY` ใน `.env` (หรือ Environment ของ Render) — key อยู่ฝั่งเซิร์ฟเวอร์เท่านั้น ไม่ถูกส่งไปหน้าเว็บ
ถ้าไม่ใส่ key เว็บส่วนอื่นยังใช้งานได้ หน้า AI จะแจ้งว่ายังไม่พร้อมและแนะนำให้ใช้การตรวจอาการแบบเลือกรายการแทน

## บัญชีทดสอบสำหรับผู้ประเมิน
ใส่ `DEMO_PASSWORD` (และ `DEMO_USERNAME` ถ้าไม่ใช้ชื่อ `demo`) แล้วรีสตาร์ท ระบบจะสร้างบัญชีพร้อมอุปกรณ์ 3 เครื่อง การแจ้งเตือน (มีงานเลยกำหนด 1 งาน) และประวัติตัวอย่าง
บน Render รุ่นฟรีฐานข้อมูลถูกล้างเมื่อ deploy ใหม่ บัญชีนี้จะถูกสร้างใหม่ให้อัตโนมัติ

> ถ้ามีข้อมูลที่บันทึกไว้ตั้งแต่ก่อนมีระบบสมาชิก ข้อมูลนั้นจะเป็นของ**บัญชีแรก**ที่สมัคร

## ตั้งค่าแจ้งเตือนผ่าน LINE
ใช้ LINE Messaging API (LINE Notify ปิดบริการแล้วเมื่อ 31 มี.ค. 2025)

### ฝั่งผู้ดูแลระบบ (ทำครั้งเดียว)
1. สร้าง LINE Official Account ที่ https://manager.line.biz (ฟรี)
2. ใน LINE Official Account Manager ไปที่ **Settings > Messaging API** กด **Enable Messaging API** แล้วสร้าง Provider ใหม่
3. ใน **Settings > Response settings**
   - เปิด **Webhooks**
   - ปิด **Auto-response messages** และ **Greeting message** (ระบบตอบข้อความเอง)
4. เข้า https://developers.line.biz/console/ เลือก Provider และช่องที่สร้างไว้
   - แท็บ **Basic settings** → คัดลอก **Channel secret**
   - แท็บ **Messaging API** → เลื่อนลงล่างสุด กด **Issue** ที่ *Channel access token (long-lived)* แล้วคัดลอก
5. คัดลอก `.env.example` เป็น `.env` แล้วกรอก `LINE_CHANNEL_ACCESS_TOKEN` และ `LINE_CHANNEL_SECRET`
6. เมื่อนำเว็บขึ้นออนไลน์แล้ว ไปที่แท็บ **Messaging API** ช่อง **Webhook URL** ใส่ `https://<โดเมนของเว็บ>/webhook/line`
   กด **Verify** (ต้องขึ้น Success) แล้วเปิด **Use webhook**

### ฝั่งผู้ใช้
1. เข้าเว็บ ไปที่เมนู **แจ้งเตือน** แล้วกด **เชื่อมต่อ LINE**
2. กด **+ เพิ่มเพื่อน** เพื่อแอดบัญชี DeviceCare
3. พิมพ์รหัส 6 หลักที่เห็นบนเว็บ ส่งเข้าแชต (รหัสใช้ได้ 15 นาที)
4. บอทตอบ “✅ เชื่อมต่อสำเร็จ” และหน้าเว็บอัปเดตเอง

### ทดสอบบนเครื่องตัวเอง (localhost)
LINE ส่ง webhook มาที่ `localhost` ไม่ได้ จึงเชื่อมต่อด้วยรหัสไม่ได้ ให้ใส่ `LINE_USER_ID` (แท็บ **Basic settings** → **Your user ID**) ใน `.env`
ระบบจะผูก LINE นั้นให้**บัญชีแรก**ที่สมัครในเว็บโดยอัตโนมัติ

### หมายเหตุ
- เซิร์ฟเวอร์ต้องทำงานอยู่ถึงจะส่งแจ้งเตือนได้ (ปิดหน้าเว็บได้)
- LINE Official Account แพ็กเกจฟรีมีโควตาข้อความ push ต่อเดือนจำกัด (ข้อความที่บอทตอบกลับในแชตไม่นับโควตา)
- ห้ามแชร์ไฟล์ `.env` และห้ามอัปขึ้น GitHub เพราะมี token (อยู่ใน `.gitignore` แล้ว)

## ฐานข้อมูล
ใช้ SQLite (`node:sqlite` ที่มีมากับ Node.js) ไฟล์อยู่ที่ `data/devicecare.db` และสร้างให้อัตโนมัติในครั้งแรกที่รัน
เปลี่ยนตำแหน่งไฟล์ได้ด้วยตัวแปร `DB_PATH` และเปลี่ยนพอร์ตด้วย `PORT`

| ตาราง | เก็บข้อมูล |
|---|---|
| `users` | บัญชีผู้ใช้ (รหัสผ่านเก็บแบบ scrypt hash) และการเชื่อมต่อ LINE |
| `sessions` | การเข้าสู่ระบบ (หมดอายุ 30 วัน) |
| `devices` | อุปกรณ์ของผู้ใช้แต่ละคน |
| `symptoms` | อาการ ขั้นตอนตรวจสอบ และกรณีที่ควรติดต่อช่าง |
| `guides` | คู่มือการดูแล |
| `reminders` | การแจ้งเตือนและรอบการดูแล |
| `records` | ประวัติการดูแล ตรวจอาการ และซ่อมแซม พร้อมค่าใช้จ่าย |
| `diagnosis_logs` | สถิติการใช้ระบบตรวจอาการ (ใช้ประเมินผลว่าปัญหาใดพบบ่อย) |

ประเภทอุปกรณ์ อาการ และคู่มือ กำหนดไว้ที่ `seed.js` แก้แล้วรีสตาร์ทเซิร์ฟเวอร์ ระบบจะซิงก์ลงฐานข้อมูลให้เอง โดยข้อมูลของผู้ใช้ยังอยู่ครบ

ประเภทอุปกรณ์ที่รองรับ: โน้ตบุ๊ก, คอมพิวเตอร์ตั้งโต๊ะ, แท็บเล็ต, สมาร์ตโฟน, จอมอนิเตอร์, เครื่องพิมพ์, เมาส์/คีย์บอร์ด, หูฟัง, ฮาร์ดดิสก์/แฟลชไดรฟ์ และอุปกรณ์อื่น ๆ

## API
ทุก API (ยกเว้นที่ระบุ) ต้องเข้าสู่ระบบก่อน และเห็นเฉพาะข้อมูลของตัวเอง

| Method | Path | คำอธิบาย |
|---|---|---|
| POST | `/api/auth/register` | สมัครสมาชิก (ไม่ต้องล็อกอิน) |
| POST | `/api/auth/login` | เข้าสู่ระบบ (ไม่ต้องล็อกอิน) |
| POST | `/api/auth/logout` | ออกจากระบบ |
| GET | `/api/auth/me` | ข้อมูลผู้ใช้ที่ล็อกอินอยู่ |
| GET | `/api/device-types` | ประเภทอุปกรณ์ที่รองรับ (ไม่ต้องล็อกอิน) |
| GET/POST | `/api/devices` | รายการและเพิ่มอุปกรณ์ |
| PUT/DELETE | `/api/devices/:id` | แก้ไขและลบอุปกรณ์ |
| GET | `/api/symptoms?type=laptop` | อาการตามประเภทอุปกรณ์ |
| POST | `/api/diagnoses` | บันทึกสถิติการตรวจอาการ |
| GET | `/api/guides` | คู่มือ |
| GET/POST | `/api/reminders` | รายการและเพิ่มการแจ้งเตือน |
| POST | `/api/reminders/:id/complete` | ทำเสร็จแล้ว: บันทึกประวัติและเลื่อนกำหนด |
| DELETE | `/api/reminders/:id` | ลบการแจ้งเตือน |
| GET/POST | `/api/records?device_id=` | ประวัติ |
| DELETE | `/api/records/:id` | ลบประวัติ |
| GET | `/api/dashboard` | ข้อมูลสรุป |
| GET | `/api/line` | สถานะการเชื่อมต่อ LINE ของผู้ใช้ |
| POST | `/api/line/link-code` | ขอรหัส 6 หลักสำหรับเชื่อมต่อ LINE |
| POST | `/api/line/unlink` | ยกเลิกการเชื่อมต่อ LINE |
| POST | `/api/line/test` | ส่งข้อความทดสอบเข้า LINE |
| POST | `/api/line/send-now` | ส่งสรุปงานที่ถึงกำหนดเข้า LINE ทันที |
| GET | `/api/admin/stats` | สถิติรวม (เฉพาะผู้ดูแลระบบ) |
| GET | `/api/admin/table?name=` | ข้อมูลในตาราง แบ่งหน้า (เฉพาะผู้ดูแลระบบ) |
| GET | `/api/admin/table.csv?name=` | ดาวน์โหลดตารางเป็น CSV (เฉพาะผู้ดูแลระบบ) |
| POST | `/webhook/line` | รับเหตุการณ์จาก LINE (ตรวจลายเซ็นด้วย Channel secret) |

## ข้อจำกัดของต้นแบบ
- ยังไม่มีระบบลืมรหัสผ่าน
- การแจ้งเตือนผ่านเบราว์เซอร์ทำงานเฉพาะตอนเปิดเว็บค้างไว้ ถ้าต้องการแจ้งเตือนตอนปิดเว็บให้ใช้ LINE
